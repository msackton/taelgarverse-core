# Entity map review in Obsidian

The desktop **Session review** tab now focuses on entity maps. Enable
**Settings → Taelgarverse → Enable session review**, then run
**Taelgarverse: Open session review**. The session list has exactly two actions:
**Show entities map** and **Review entities**. Only mapped sessions are listed;
discovery errors remain visible. Search uses campaign, session number, and YAML path.

A session is **Unreviewed** whenever any included entity is not `humanReviewed`.
High-confidence or `automatedReviewed` entities still require human review. Counts
are local discovery hints; opening a map checks registered transcript, session
metadata, map, and feedback fingerprints. Vault-note content hashes are not
processing inputs: note edits do not block review or reset human decisions.
Existing maps' legacy `inputs.vaultNotes` hashes are ignored and removed on the
next guarded map save. Linked targets must still be valid vault paths.

A changed transcript or session metadata opens a confirmation screen before the
map or queue. **Continue with current transcript** accepts only the displayed
revision, updates the recorded source fingerprints, and records a
`confirmSourceChanges` event with before/after maps in review history. Existing
decisions/statuses are retained; confirmation does not imply semantic rechecking.
If sources change again before confirmation, reload and confirm the new revision.
Source UIDs and whole-turn boundaries must still validate; confirmation cannot
repair broken evidence references. Other map/review concurrency guards remain.

## Table and queue

**Show entities map** starts with one bar containing **Back to sessions**,
**Entity-by-entity review**, **Reload list**, and operation status. Its title shows
the campaign/session, known in-world date range, real-world date, and **List of
Entities**. Missing dates are omitted. The following line shows the pending human
review count and **Transcript** / **Session note** links when those files exist.
The session note uses the campaign registry's `campaignRoot` and `notePattern`,
with the vault's two-digit minimum for `{session_padded}` (e.g. `01`, `12`, `123`);
missing files have no link. A prepared narrative is never labeled as a transcript.

The included table has **Entity**, **Type**, **Status**, **Role**, **Details**,
**Accept**, and **Exclude** columns. Entity cells retain the session name, matching
vault note, source names, and later-identification/Mirror flags. Internal IDs and
the raw metadata tagline are hidden. A read-only **Confidence: High / Medium / Low**
badge appears beneath each entity name in both the table and one-at-a-time view.
It reports the agent's confidence in the full inclusion/identity/type/role decision,
separately from human review status; accepting an entity does not change it.
When recorded, the agent's one-sentence `confidenceExplanation` appears next to
the badge in per-entity review and inside the main list's **Details** popup.
The entity skill requires it for new/revised medium- or low-confidence decisions;
high-confidence explanations are optional. Existing maps remain readable, and
missing explanations are shown as unrecorded rather than generated by the UI.
Vault links show the note name, with the
full path on hover. Type, status, and role dropdowns save their selected field
immediately without implicitly approving other fields. **Accept** marks the row
human reviewed. Failed inline saves show an error and restore the prior value.

**Details** opens a modal popup containing verbatim source passages and active agent
feedback, with a field for another question. Close it with **Close**, Escape, or
a click on the backdrop; focus returns to the Details button. Source links open the actual local
UID-resolved editor line. Included and excluded passages load only on demand;
both polished transcripts and registered prepared narratives are supported.

**Exclude** opens a reason form beneath the row's controls, spanning Type through
Exclude while keeping the entity identity at the left. It asks for a short reason
(at most 40 words), then moves the entity into
the **Excluded entities** table. That table has **Name / label**, **Exclusion
reason**, **Details**, and **Include** columns. Details opens the same popup with source passages.
Include restores a previously included entity's ID, fields, links, flags, and
evidence, retaining feedback/history and resetting it to unreviewed. Original
excluded candidates have no saved type/role, so Include requires those selections
before creating an unreviewed included record. It never guesses classifications.
Exclusion/inclusion are guarded, recoverable saves; source files are unchanged.

**Review entities** retains its one-at-a-time editor for **Name in this session**,
**Entity type**, **Role in this session**, and **Linked vault note**. The session
name changes the map's display text; it does not rename the vault note. New links
are inspected before saving. Choosing a target clears unresolved alternatives;
clearing it also clears the later-identification flag. Changing an item to another
type clears its item-only Mirror flag. **Reopen review** saves edits and marks a
reviewed entity as needing another review. **Exclude and next** asks for the same
short reason as the map's Exclude action, saves pending edits into the archived
record, moves the entity to **Excluded entities**, and advances. Include on the
main map restores that record with its evidence and confidence explanation.
For an entity without a linked vault page, **Create staging note** is available
in the per-entity screen and the included entity's **Details** popup on the main
map. It opens a name
prompt and previews `Worldbuilding/Staging/<campaign folder>/<name>.md`. Named
entities have a suggested name; descriptive/unnamed labels require a name to be
entered. Existing short campaign folders are reused when they uniquely match the
registry's canonical name or aliases (e.g. `Dunmar` and `Chasm`); otherwise the
canonical campaign name is used for a new folder. Missing directories are created.
The file is empty: no frontmatter, template, or prose is inserted. Creation saves
current entity edits, links the new file, keeps the same entity on screen, and
sets it unreviewed. The dialog shows progress while creating/linking, then closes
and focuses that entity's new vault-note link on success. From the main map,
the name prompt replaces Details and creation refreshes the row. Errors remain in the dialog for
correction and retry. Existing files, case-insensitive filename/name/alias collisions,
unsafe paths, and stale review tokens are rejected. If saving the link is
interrupted, the empty note is retained and its path is reported; reload to recover
the guarded map/history transaction before trying again.

The Obsidian action uses its live Markdown-file and metadata index for filename,
name, and alias collision checks. Only notes missing cached metadata need a file
read; this avoids reopening the whole vault for each creation. Direct helper calls
without that index retain the full collision scan.

**Explain this change (optional)** contains a change note saved with an edit in
**Change history**, so the agent can understand the correction. It can prefill the
exclusion reason, which is confirmed separately. Every edit/exclusion records the
old/new decision and retains the excluded record. There is no automatic deletion of session files.

The default queue includes every included entity not human reviewed; **All entities**
also allows reopening completed decisions. **Skip for now** and **Previous** navigate
without saving. **Save and next** saves all form edits, marks the entity human
reviewed, and advances to the next entity. It also works when no fields changed.
Returning to the session list refreshes its counts. Empty maps have zero pending included entities.
Excluded candidates are not part of the included-entity review count. Request
complex splits, merges, additions, or exclusion revisions through feedback for the agent.

## Feedback and agent handoff

**Feedback on this entity** saves a comment/question about the displayed entity.
**Feedback on this session** appears only on the main entities map and accepts
missing-entity requests or corrections about the whole map. The entity-by-entity
screen keeps only entity feedback; **Follow up with the agent** and **Change
history** are also restricted to the main map. Both feedback forms save messages
for the agent to read when asked to work
on the saved feedback; saving does not run the agent. **Change history** is a
separate section showing saved edits and change notes, including removed entities.
Comments do not change review status. Use **Reopen review** to reopen a
record that needs another human review. Feedback is saved in
`cleaned/<stem>-entities-review.json`, beside `*-entity-map.json`; a link appears
after the first save. Merely opening review never creates a file.

For a question that needs agent help:

1. Save the question under **Feedback on this entity** or **Feedback on this session**.
2. Leave the entity unreviewed and choose **Skip for now** in the queue to continue
   reviewing others. If already reviewed, choose **Reopen review** in the queue or
   set its table **Status** to **Unreviewed**.
3. On the main entities map, expand **Follow up with the agent** and paste its session-specific request
   into an agent chat with vault access. The section opens automatically when
   there are open questions. Work through the saved questions with the agent;
   it records a resolution only after checking the agreed outcome.
4. Choose **Reload list** in the map or **Reload entities** in the queue. Inspect
   the result, then **Accept** the table row or use **Save and next** when satisfied.
   A resolved question does not itself supply human approval.

Entity cards show their open-question count; saved comments display **Waiting for
agent** or **Resolved**, with the resolution explanation. These are feedback
states, separate from whether the entity has been human reviewed. An open question
does not automatically start an agent or block an explicit human approval.

The vault's `check-session-entities` skill understands this JSON and these requests:

- **Recalibrate skill based on feedback:** inspect corrections and original
  confidence/reasons, reconcile their snapshots, and update supported skill rules
  and examples. Session-specific edits do not automatically become general rules.
- **Resolve feedback with my help:** inspect open issues and supporting passages,
  work through questions with the human, apply agreed changes through guarded
  saves, and record a resolution only after checking the outcome.

Human corrections remain in history. Agent resolutions do not create human approval.
Vault-note edits do not reset decisions or review status. Changed transcript/session
inputs require explicit confirmation, which preserves existing decisions and
records the acknowledged revision; changed decisions still need actual review.
Regeneration appends an agent event and cannot overwrite whole human-reviewed
records, forge new human statuses, or recreate removed IDs. Reopen a protected
record as unreviewed before asking an agent to revise it. Historical calibration
exports are preserved and are not automatically replayed or migrated.

## Setup, persistence, and recovery

Discovery runs in JavaScript without Python. Review requires Python 3.9+ and the
vault's maintained `.agents/skills/check-session-entities/scripts/entity_review.py`
and its source-reader dependencies. Install the entity skill requirements, e.g.:

```powershell
python -m pip install -r D:\personal\taelgar\.agents\skills\check-session-entities\requirements.txt
```

Configure the Python executable in Taelgarverse settings when needed. The desktop
adapter invokes Python without a shell using UTF-8 JSON stdin/stdout. Windows
uses the existing native executable resolution and forward-slash launch paths.
Requests have a 60-second timeout, 16 MiB output limit, and callback watchdog.
Errors stay visible beside the form; failed writes do not advance the queue.
The lower-level Python setup/connection commands remain available to adapter tests;
the focused session UI no longer contains transcript repair or connection tools.

Map and review writes share the session lock. Review JSON contains version 1,
purpose `session-entities-review`, the session YAML, current map byte hash,
history, and open/resolved feedback. Optional `excludedRecords` stores the full
records of entities excluded through the UI, paired with their exact map exclusion;
reinclusion consumes that entry. Agent regeneration must retain those exclusions
and cannot recreate their IDs while they remain excluded. Each human change includes before/after
snapshots and exact map hashes. Agent regeneration records whole-map snapshots.
A write-ahead transaction inside the review file allows the next inspection to
complete an interrupted two-file save if the map still matches its before/after
hash. Unexpected external changes stop for reconciliation; never edit hashes to
bypass the guard. Refresh/reinspect after a stale-token failure.

This replaces the old provisional `reviewState` queue and high-confidence default
acceptance. The current entity-map schema does not accept `reviewState`; unsupported
legacy maps need the entity skill's explicit upgrade. Existing transcript review
artifacts and helpers are preserved, but transcript repair is outside this tab.
No final interaction generation or automatic agent execution is added.

## Ownership and checks

Core owns the desktop adapter, native index, DOM table/queue, and plugin styles.
The vault owns source validation, guarded edits, review JSON, locks, and recoverable
writes in `entity_review.py` and `entity_review_store.py`. `entity_map.py` uses the
same store when regenerating a reviewed map. See the vault skill's
`references/review-workflow.md` for the agent API and feedback semantics.

Run core's entity/session review, index, process, Python-resolution, and Obsidian
adapter tests, plus `node scripts/build-obsidian.mjs`. Run the vault entity suite
with `python3 -B -m unittest discover -s .agents/skills/check-session-entities/tests -v`.
Use temporary bundles for save/recovery tests. A local plugin build does not install
or release it. Development installation, when requested, uses:

```powershell
npm run dev -- --plugin --vault D:\personal\taelgar
```
